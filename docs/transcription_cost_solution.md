# MindEcho 转录成本解决方案

> 编写日期：2026-08-04
> 背景：MindEcho 使用 AssemblyAI 进行语音转文字（含说话人分离），目标用户为青少年学生，成本敏感度极高

---

## 1. 问题分析

### 1.1 当前成本现状

| 项目 | 数据 |
|------|------|
| 当前方案 | AssemblyAI Universal-2 + Speaker Diarization |
| 基础转录 | $0.15/hr（Universal-2） |
| 说话人分离 | +$0.02/hr |
| **合计** | **$0.17/hr** |
| 典型日使用量（30min） | $0.085/天 |
| 月成本（每天30min） | ~$2.55/月 |
| 月成本（每天2hr） | ~$10.20/月 |

> 数据来源：AssemblyAI 官方定价页（https://www.assemblyai.com/pricing）

### 1.2 为什么这是个问题

1. **目标用户是青少年/学生** — 没有信用卡、零花钱有限，无法承担持续云 API 费用
2. **比赛场景** — OPC 比赛评审关注商业化可行性，持续云成本影响商业模式
3. **隐私承诺** — 产品核心卖点是"隐私优先"，但当前录音文件必须上传到 AssemblyAI 服务器
4. **规模化后成本失控** — 如果 1000 个用户每天录 30 分钟，月成本 = $2,550

## 2. 可选方案对比

### 方案总览

### 2.1 方案 A：保持 AssemblyAI（当前方案）

**成本：** $0.17/hr（含说话人分离）

**优点：**
- 已集成，无需额外开发
- 说话人分离质量好
- 中文支持优秀
- 无文件大小限制

**缺点：**
- 持续的云成本，对青少年用户不友好
- 录音文件必须上传到外部服务器，与隐私承诺冲突
- 免费额度有限（$50 试用），用完即止

**结论：** 不适合作为长期方案，但可以作为"高级功能"保留

### 2.2 方案 B：换 OpenAI Whisper API

**成本：** $0.36/hr（whisper-1），无说话人分离

**优点：**
- 集成简单（代码已定义 WhisperApi 接口）
- 多语言支持好
- 准确率高

**缺点：**
- 比 AssemblyAI 还贵（$0.36 vs $0.17/hr）
- **不支持说话人分离**
- 25MB 文件大小限制，长录音需分片
- 需要用户额外配置 OpenAI API Key

**结论：** 不推荐，更贵且功能更少

### 2.3 方案 C：换 OpenAI gpt-4o-mini-transcribe

**成本：** $0.18/hr，无说话人分离

**优点：**
- 成本与 AssemblyAI 持平（$0.18 vs $0.17/hr）
- 集成简单，与 Whisper API 同一接口
- 对清晰音频准确率足够

**缺点：**
- **不支持说话人分离**
- 25MB 文件大小限制
- 需要用户配置 OpenAI API Key（非 DeepSeek 生态）

**结论：** 价格没优势，功能倒退，不推荐

### 2.4 方案 D：换 Groq Whisper

**成本：** **$0.04/hr**（约为 AssemblyAI 的 1/4），无说话人分离

**优点：**
- 成本极低，$0.04/hr
- 推理速度极快（1小时音频 8-12秒完成）
- 使用与 OpenAI Whisper 相同模型

**缺点：**
- **不支持说话人分离**
- 25MB 文件大小限制
- Groq 为新兴平台，服务稳定性待验证
- 需要额外注册 Groq 账号

**结论：** 成本优势明显，但缺少说话人分离是硬伤，且增加用户的 API 管理复杂度

### 2.5 方案 E：Android SpeechRecognizer（本地免费）

**成本：** **$0**（完全免费）

**优点：**
- 零成本，内置在 Android 系统中
- 无需网络（支持离线语音包）
- 无需 API Key、无需任何配置
- 隐私最好（数据不出设备）

**缺点：**
- **不支持说话人分离**
- 准确率低于云端方案，尤其是中文和嘈杂环境
- 仅支持短句模式（不是长录音转录）
- 依赖 Google 服务（部分国产机型可能受限）
- 无法处理已录制的音频文件（只能实时麦克风输入）

**结论：** 免费但功能受限严重，不适合作为主要转录方案

### 2.6 方案 F：Whisper.cpp 本地部署（最推荐）

**成本：** **$0**（完全免费，完全本地运行）

**技术可行性：**
- Whisper.cpp 有官方 Android 示例（`whisper.android`）
- 通过 JNI 调用 C++ 推理引擎
- 支持模型量化（Q8_0）减少内存占用
- 支持 ARM NEON 指令集加速

**模型选择与资源占用：**

| 模型 | 大小 | 峰值内存 | 转录速度 | 中文准确率 |
|------|------|---------|---------|-----------|
| tiny（多语言） | 75MB | ~150MB | 实时~3x | ⭐⭐⭐ |
| base（多语言） | 142MB | ~500MB | 实时~2x | ⭐⭐⭐⭐ |
| small（多语言） | 466MB | ~1.2GB | 接近实时 | ⭐⭐⭐⭐⭐ |
| medium（多语言） | 1.5GB | ~2.1GB | 2-3x实时时间 | ⭐⭐⭐⭐⭐ |

> 数据来源：Whisper.cpp 官方文档（https://github.com/ggerganov/whisper.cpp）

**优点：**
- 完全免费，零运行成本
- 完全本地运行，隐私保护最强
- 支持中文（多语言模型）
- 可以选择精度/速度的平衡点
- 一次下载模型后永久使用

**缺点：**
- **不支持说话人分离**
- 模型文件较大（base 142MB，需首次下载）
- 旧设备上推理速度较慢
- 开发工作量大（JNI 绑定、C++ 编译链路）
- APK 体积增大

**结论：** 长期最优方案，但需要在比赛截止后实施

### 2.7 方案 G：混合方案 ⭐ 推荐

**核心理念：** 不依赖单一方案，根据用户场景和需求动态选择转录引擎

**分层架构：**

```
┌─────────────────────────────────────────────┐
│               用户选择层                      │
│  设置 → 转录引擎：本地 / 云端 / 自动         │
├─────────────────────────────────────────────┤
│              转录引擎路由层                   │
│  根据设置和可用性自动选择最佳引擎             │
├──────────────┬──────────────┬──────────────┤
│  本地引擎     │  低成本云端   │  高级云端     │
│  Whisper.cpp │  Groq Whisper│  AssemblyAI   │
│  免费         │  $0.04/hr   │  $0.17/hr     │
│  无说话人分离  │  无说话人分离 │  有说话人分离  │
│  完全离线     │  需网络      │  需网络        │
└──────────────┴──────────────┴──────────────┘
```

**推荐路线：**

| 阶段 | 时间 | 方案 | 成本 | 说明 |
|------|------|------|------|------|
| **Phase 1** | 现在（比赛用） | 保留 AssemblyAI + 增加免费替代提示 | $0.17/hr | 比赛期间使用现有方案，设置中提示免费替代方案 |
| **Phase 2** | 比赛后 sprint 1 | 集成 Android SpeechRecognizer 作为基础转录 | $0 | 快速实现免费转录（无说话人分离） |
| **Phase 3** | 比赛后 sprint 2 | 集成 Whisper.cpp 本地引擎 | $0 | 实现高质量本地转录 |
| **Phase 4** | 长期迭代 | 智能引擎路由 + 说话人分离优化 | $0~$0.17/hr | 用户可自由选择，默认本地 |

## 3. 推荐技术路线（详细）

### Phase 1：比赛期间快速优化（1-2天）

**目标：** 不改变现有架构，但提供成本透明度和替代路径

**改动点：**

1. **SettingsScreen 增加成本说明**
   - 在 AssemblyAI 输入框下方显示"转录成本约 $0.17/hr，建议优先使用本地方案"

2. **增加"免费转录"开关**
   - 默认使用 Android SpeechRecognizer 做基础转录
   - 仅在用户明确开启"云端转录"时才使用 AssemblyAI

3. **代码改动量：** 小（主要在 UI 层）

### Phase 2：集成 Android SpeechRecognizer（3-5天）

**目标：** 实现零成本基础转录，覆盖大部分用户场景

**架构设计：**

```
RecordingService
    ↓
TranscriptionManager (新增)
    ├── AndroidSpeechRecognizer (免费，实时)
    │   └── 录音期间实时获取转写文本
    └── AssemblyAITranscriber (云端，后处理)
        └── 录音完成后上传转写 + 说话人分离
```

**代码改动：**
- 新增 `TranscriptionManager.kt` — 统一转录接口
- 新增 `AndroidSpeechRecognizerTranscriber.kt` — 封装 SpeechRecognizer
- 修改 `RecordingScreen.kt` — 录音期间显示实时转写文本
- 修改 `SettingsScreen.kt` — 增加转录引擎选择

**关键实现要点：**
```kotlin
// TranscriptionManager.kt 接口设计
interface TranscriptionEngine {
    // 实时转录（录音期间）
    fun startRealtimeTranscription(audioStream: InputStream)
    fun stopRealtimeTranscription(): Flow<String>
    
    // 后处理转录（录音完成后）
    suspend fun transcribeFile(audioFile: File): TranscriptionResult
}

// 引擎类型
enum class TranscriptionEngineType {
    ANDROID_SPEECH_RECOGNIZER,  // 免费，本地，无说话人分离
    ASSEMBLY_AI,                // 付费，云端，有说话人分离
    WHISPER_CPP                 // 免费，本地，无说话人分离（Phase 3）
}
```

### Phase 3：集成 Whisper.cpp（1-2周）

**目标：** 实现高质量本地转录，完全摆脱云成本

**集成方式：**

```
┌───────────────────────────────────────────────┐
│                  MindEcho App                  │
├───────────────────────────────────────────────┤
│  Kotlin/Compose (UI Layer)                     │
├───────────────────────────────────────────────┤
│  WhisperManager.kt (Kotlin JNI Wrapper)        │
│      ↓ JNI calls                               │
├───────────────────────────────────────────────┤
│  libwhisper_jni.so (C++ Native Library)        │
│      ↓                                        │
│  whisper.cpp (ggml inference engine)           │
│      ↓                                        │
│  ggml-tiny.bin / ggml-base.bin (模型文件)       │
└───────────────────────────────────────────────┘
```

**实施步骤：**

1. **添加 whisper.cpp 子模块**
   ```bash
   git submodule add https://github.com/ggerganov/whisper.cpp app/src/main/cpp/whisper.cpp
   ```

2. **编写 CMakeLists.txt** — 编译 whisper.cpp 为 Android native library
   - 启用 `GGML_NO_AVX`、`GGML_NO_AVX2`（Android 不需要 x86 指令集）
   - 启用 `GGML_USE_NEON`（ARM 优化）
   - 使用 `c++_shared` STL

3. **编写 JNI 桥接层** — `whisper_jni.cpp`
   - 加载模型文件
   - 接收 PCM 音频数据
   - 返回转录文本

4. **编写 Kotlin 封装** — `WhisperManager.kt`
   - 模型下载管理（首次使用时下载）
   - 音频文件转换（AAC → WAV 16kHz mono）
   - 转录结果回调

5. **模型管理**
   - 默认使用 `ggml-tiny.bin`（75MB，速度快）
   - 可选升级 `ggml-base.bin`（142MB，准确率更高）
   - 首次启动时从 GitHub Releases 下载模型

**模型下载流程：**
```
App首次启动 → 检测模型是否存在
    ├── 不存在 → 显示下载提示（约75MB，WiFi推荐）
    │           └── 下载至 context.filesDir/whisper-models/
    └── 存在 → 直接加载
```

### Phase 4：智能引擎路由 + 说话人分离优化（长期）

**目标：** 根据用户场景自动选择最优转录引擎

**路由逻辑：**

```
用户录音完成
    ↓
判断用户设置
    ├── 仅本地模式 → Whisper.cpp / Android SpeechRecognizer
    │                 （免费，无说话人分离）
    ├── 仅云端模式 → AssemblyAI / Groq
    │                 （付费，按需使用）
    └── 智能模式（默认）
        ├── 短录音(<5min) → Whisper.cpp（免费，快速）
        ├── 长录音(>5min) → 显示选项让用户选择
        │   ├── 快速转录（免费，无说话人分离）
        │   └── 完整转录（云端，需 API Key）
        └── 需要说话人分离 → AssemblyAI（仅此场景用云端）
```

## 5. 对比赛商业方案的影响

### 定价策略优化

**原方案：**
- App 基础版：免费 → 但转录成本 $0.17/hr，不可持续
- App 高级版：¥29/月 → 无法覆盖重度用户的 AssemblyAI 成本

**优化后：**
- **App 基础版**：免费 + 本地转录（Whisper.cpp）→ 零成本，真正可持续
- **App 高级版**：¥19/月 → 云端转录 + 说话人分离 + 无限时长
- **硬件用户**：免费使用本地转录，硬件利润覆盖开发成本

### 商业模型优势

1. **边际成本趋近于零** — 大部分用户使用本地转录，服务器成本忽略不计
2. **免费模式可持续** — 不需要用户补贴云 API 费用
3. **高级版价值明确** — 说话人分离是"杀功能"，愿意付费的用户才需要承担云成本
4. **隐私卖点强化** — "所有录音都在你的手机上处理，不上传任何音频文件"

## 7. 技术可行性验证

### Whisper.cpp Android 可行性

- **官方支持**：Whisper.cpp 项目提供完整的 Android 示例（`whisper.android.java`）
- **硬件要求**：base 模型 142MB，峰值内存 ~500MB，主流 Android 设备均可运行
- **中文支持**：多语言模型支持中文，small 以上模型中文准确率较高
- **推理速度**：tiny 模型在骁龙 8 系芯片上可达实时 3x 速度
- **量化支持**：Q8_0 量化几乎无损，可进一步降低内存占用

### 风险与缓解

| 风险 | 概率 | 缓解措施 |
|------|------|---------|
| 旧设备推理速度慢 | 中 | 降级到 tiny 模型；提供云端转录作为备选 |
| 模型下载失败 | 低 | 断点续传；内置 MD5 校验；提供手动下载指引 |
| 中文准确率不足 | 低 | small 以上模型中文足够好；关键场景可回退到云端 |
| APK 体积增大 | 高 | 模型不打包在 APK 中，首次运行时按需下载 |
| 比赛前无法完成 | 高 | **Phase 1 先做 UI 优化，完整的 Whisper 集成放赛后** |
